# Aplicar, corrigir e retomar

## Aplicar

- Oriente resposta sem consulta quando a prática for autônoma, com código em bloco e decisões justificadas.
- Aceite respostas em conjunto ou lotes e preserve-as literalmente.
- Durante a tentativa, apenas confirme recebimento; revele resultado ou correção somente no limite de feedback escolhido pelo usuário.
- Encerre quando todos os itens forem respondidos ou quando o usuário pedir correção. Itens ausentes são `Não respondida`, não erro conceitual.

## Corrigir

Para cada item registre `Correta`, `Parcial`, `Incorreta` ou `Não respondida`, a evidência concreta, o raciocínio correto quando necessário, a causa do erro, feedback acionável e gaps relevantes.

Aceite implementações alternativas válidas. Diferencie erro conceitual, interpretação, sintaxe, caso-limite, justificativa insuficiente e trade-off diferente. Em código, considere comportamento, complexidade, legibilidade, testes e requisitos, não apenas compilação. Use no máximo uma variação curta quando precisar verificar uma correção e não produza nota global artificial.

## Retomar ou variar

Procure listas compatíveis com itens sem resposta ou correção. Retome uma única lista ativa; se houver várias, apresente data, quantidade e andamento para escolha. Para nova lista, use o histórico para variar contextos e priorizar gaps sem repetir questões.
